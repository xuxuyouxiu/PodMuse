# 用户故事 — 增强搜索

**需求 ID：** ICE 10.5（排名 8）
**版本：** v1.12.0
**状态：** 规划中
**创建日期：** 2026-07-19

---

## 背景与现状

项目已存在 `search:notes` IPC + 顶栏 Ctrl+K 搜索框（`src/renderer/components/Header.tsx`），实现方式为递归遍历 Obsidian 目录下所有 `.md`，对**文件名 + 全文内容**做 `String.toLowerCase().includes(query)` 子串匹配，硬上限 30 条。

**主要不足：**
- 无分词、无倒排索引、无相关性排序
- 不能按 frontmatter 字段过滤（date 范围、category、show、tags）
- 不能按实体过滤（"哪些播客提到了张三"）
- 结果无 facet 分组、无高亮、无分页
- `parseFrontmatter` 只解析 6 个 key，缺 title/host/guest/platform

**目标：** 在不引入外部搜索库（lunr/flexsearch）的前提下，复用现有 `buildPodcastFileMap` / `buildTagIndex` / `parseFrontmatter` 基础设施，把搜索从"能搜到"升级到"能精准定位"，支持结构化筛选 + facet 浏览。

**不做：** 语义搜索（需 embedding + 向量库，工作量大，ROI 低，留待用户反馈后评估）。

---

## US-001 增强搜索后端 — 结构化查询与高亮（P0）

**作为** 播客笔记用户，**我想** 用一个关键词搜出所有相关笔记并看到精准匹配的高亮位置和上下文摘要，**以便** 快速判断哪条笔记值得打开看。

**验收标准：**

1. 新增 IPC channel `search:enhanced`，入参为 `SearchParams` 对象（见 PRD 类型定义），出参为 `SearchResult[]`。
2. 返回结果包含字段：`path`、`title`（frontmatter.title 优先，回退到文件名）、`date`、`category`、`show`、`tags[]`、`excerpt`（前后 80 字符上下文，关键词处用 `<mark>` 包裹）、`matchType`（'title' | 'content' | 'tags'）、`score`（命中次数 + 字段权重）。
3. 同一关键词同时匹配 title、content、tags，三个字段都命中的笔记排在前面。
4. 默认按 score 降序、次按 date 降序，支持 `sortBy` 参数切换为 date_desc / date_asc。
5. 支持分页：`limit` 默认 50、`offset` 默认 0，返回总数 `total`。
6. 性能：1000 个 .md 文件全量搜索返回时间 < 800ms。
7. 兼容现有顶栏 Ctrl+K 搜索：保留 `search:notes` 不动，避免破坏旧 UI。

## US-002 多维度筛选 facet（P1）

**作为** 已积累几十期播客笔记的用户，**我想** 在搜索时按分类、标签、节目、日期范围筛选，**以便** 从大量结果中快速收敛到我要的那一期。

**验收标准：**

1. `SearchParams` 支持 `filters` 对象，包含 `category?`、`tags?`（string[]，OR 关系）、`show?`（节目名）、`dateFrom?` / `dateTo?`（YYYY-MM-DD）。
2. facet 统计接口 `search:facets` 返回当前 Obsidian 库下所有可选 facet 值及对应笔记数：`categories[]`、`tags[]`（按 count 降序）、`shows[]`（按 count 降序）、`dateRange`（最早/最晚日期）。
3. 过滤逻辑：category 为 AND 关系（只选一个），tags 为 OR 关系，date 范围闭区间。
4. 当用户选了 filter 后，facet 列表要根据已选 filter 二次过滤（类似电商筛选交互，避免选出 0 结果的 facet 值）。
5. facet 数据可缓存（同一次会话内 obsidian 目录未变更时复用），通过文件 mtime 失效。

## US-003 搜索独立视图与 facet UI（P1）

**作为** 用户，**我想** 在侧边栏有一个"搜索"独立 tab，带 facet 筛选面板和结果列表，**以便** 不只是顶栏弹一下，能稳定展开搜索会话。

**验收标准：**

1. `WorkspaceSidebar` 新增第 3 个 nav item "搜索"（图标 `Search`），切换到 `SearchPanel` 组件。
2. `SearchPanel` 布局：顶部搜索输入框 + 右侧排序切换（相关度/最新/最早） + 左侧 facet 面板（分类/标签/节目/日期范围）+ 中间结果列表 + 分页控件。
3. 每条结果卡片：标题、日期、分类徽章、节目标签、tags chips、excerpt（带 `<mark>` 高亮）、"在 Obsidian 中打开" 按钮。
4. facet 面板支持多选（tags 可多选，category/show 单选），点击立即更新结果。
5. 日期范围用两个 `<input type="date">`，选择后立即更新。
6. 空状态友好提示："输入关键词或选择筛选条件开始搜索"。
7. 顶栏 Ctrl+K 快捷搜索保留（高频快速查询场景）。
8. 搜索结果为空时显示："未找到相关笔记，试试调整筛选条件"。

## US-004 按实体筛选 — "哪些播客提到了这个人/项目"（P2）

**作为** 关注某个人物/项目/概念的用户，**我想** 选定一个实体后快速看到所有提到它的播客笔记，**以便** 做主题追踪（例：张三最近半年在哪些节目都说了什么）。

**验收标准：**

1. facet 面板新增"实体"区，列出 Top 20 高频实体（来自 `buildBacklinkIndex`），点击进入实体选择器。
2. 实体选择器：分类 tab（人物/项目/概念/术语） + 搜索框 + 实体列表，点击选中后返回 facet。
3. 选中实体后，搜索结果限定为该实体反向链接面板列出的播客笔记集合。
4. 实体筛选可与其他 facet（category/tags/date）叠加。
5. 多选最多 3 个实体，结果为 OR 关系（任一提及）。

## 非功能需求

1. 不引入外部搜索库（lunr/flexsearch/fuse.js），保持依赖最小。
2. 中文分词采用字符级 bigram（`中文` → `中文`、`文搜`），不引入 jieba 等中文分词库。
3. 索引按需构建，启动时不预热（避免拖慢应用启动）。
4. 大库（>500 篇）搜索仍可接受延迟（<1s）。
5. 搜索框输入防抖 300ms。
