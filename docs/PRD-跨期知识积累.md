## 1. 背景与目标

### 1.1 背景

播客笔记助手已实现实体卡片（人物/项目/概念/术语）的自动生成和 Obsidian 反向链接面板。当前反链面板能展示"哪些播客提到了这个实体"，但仅以文件名列表形式呈现，缺少上下文和演变视角。用户看到"张三出现在 3 期播客中"后，仍需逐个打开笔记文件才能了解张三在各期说了什么、观点有何变化。

跨期知识积累的目标是在现有反链索引基础上，为实体增加时间线视图、上下文摘要和关系图谱，让用户在应用内即可纵览某实体跨多期播客的完整知识画像。

### 1.2 目标用户

| 用户角色 | 特征描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| 知识管理者 | 长期积累播客笔记，依赖 Obsidian 构建个人知识库 | 快速回顾某实体在多期播客中的演变 | 回顾某人物近三个月在播客中的观点变化 |
| 内容研究者 | 系统性地追踪特定话题/人物/项目 | 发现跨播客的隐性关联 | 研究某项目在不同节目中的报道差异 |
| 播客重度听众 | 每周听多集，积累大量实体卡片 | 避免重复学习，快速定位之前听过的内容 | 记不清某概念在哪期讲过，快速找到 |

### 1.3 业务目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
|------|---------|--------|---------|
| 提升跨期回顾效率 | 查看某实体跨期信息所需操作次数 | 从"打开N个文件"降至"1次点击展开" | 手动测试验证 |
| 增加知识关联面板使用率 | 知识关联面板日均点击次数 | 提升 50% | 用户反馈 |
| 实体卡片信息完整度 | 实体卡片含跨期摘要的比例 | > 80%（≥2次提及的实体） | 文件扫描统计 |

## 2. 需求概述

在现有反向链接面板基础上，为实体增加跨期知识积累能力：时间线视图（按时间排列每次提及并附带上下文摘要）、跨期观点对比、实体关系图谱、实体卡片自动更新"近期提及"段落。

## 3. 功能详细设计

### 3.1 实体时间线视图（US-001）

**功能描述**：用户在知识关联面板选中某实体后，展开显示按时间倒序排列的提及记录列表，每条记录包含节目名、期数、日期和上下文摘要。

**优先级**：P0

**业务规则**：
1. 数据来源：复用 backlinks.ts 已有的 BacklinkEntry 索引，扩展 PodcastRef 结构增加 episode 字段
2. 上下文摘要：从播客笔记 .md 文件中搜索实体名称，截取前后各约 100 字符
3. 排序规则：按 date 降序（最近排最前），无 date 的排末尾
4. 摘要长度：每条最多 2 行文本（约 200 字符），超出部分以"…"截断
5. 点击行为：点击某条记录在 Obsidian 中打开对应笔记文件

**交互流程**：
1. 用户在左侧栏点击"知识关联"进入反链面板
2. 面板列出所有实体（按引用次数降序），复用现有展示
3. 用户点击某实体项展开
4. 展开内容从现有的"文件名列表"变为"时间线卡片列表"
5. 每张时间线卡片显示：日期 + 期数 + 节目名 + 上下文摘要
6. 用户点击某张卡片，在 Obsidian 中打开笔记

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 播客笔记文件已删除/移动 | 跳过该条记录 | 无提示（静默跳过） |
| 实体名称在笔记中找不到（被修改过） | 摘要显示"无法提取上下文" | 该条摘要区域显示灰色提示 |
| frontmatter 缺少 episode 字段 | 期数位置不显示 | 仅显示日期和节目名 |
| 笔记文件过大（>500KB） | 只搜索前 10000 字符 | 正常显示摘要 |

### 3.2 跨期观点对比（US-002）

**功能描述**：用户可选择 2-3 期播客，并排查看同一实体在不同期的上下文摘要，快速发现观点变化。

**优先级**：P1

**业务规则**：
1. 对比入口：仅当实体有 ≥ 2 条时间线记录时显示"对比"按钮
2. 选择数量：支持 2-3 期对比
3. 对比布局：2 期对比为左右并排，3 期对比为三栏
4. 差异标注：按句子分割，新增的句子标记绿色背景，删除的标记红色背景（与上期对比）
5. 关闭对比后回到时间线列表视图

### 3.3 实体关系图谱（US-003）

**功能描述**：以节点-连线形式展示实体间共现关系，节点大小反映出现频次，连线粗细反映共现次数。

**优先级**：P1

**业务规则**：
1. 数据来源：复用 BacklinkPanel.tsx 已有的 computeCoEntities() 函数
2. 渲染方式：SVG，节点数一般 < 50
3. 节点样式：大小按 podcastRefs.length 映射（1次最小，10+次最大），颜色按实体类型区分（人物蓝、项目绿、概念紫、术语橙）
4. 连线样式：粗细按共现次数映射（1次最细，5+次最粗），标注共现次数
5. 交互：点击节点高亮该节点的所有关联连线，并跳转到该实体的时间线视图
6. 布局：圆形排列（简单稳定），或力导向布局（可选）

### 3.4 实体卡片自动更新摘要（US-004）

**功能描述**：处理完一期播客后，自动在实体卡片 .md 文件的"## 近期提及"段落下更新最近 3 次被提及的记录。

**优先级**：P2

**业务规则**：
1. 触发时机：processPodcast 完成且实体卡片写入后
2. 段落格式：`## 近期提及` 标题下，每条格式为 `- [[播客标题]] (2026-06-22 第89期)`
3. 保留数量：最多 3 条，按日期降序排列
4. 更新方式：正则匹配 `## 近期提及` 段落，存在则替换内容，不存在则在文件末尾追加
5. 不影响实体卡片的其他内容（核心观点、时间轴等）

## 4. 数据模型变更

### 4.1 PodcastRef 扩展

```typescript
interface PodcastRef {
  path: string       // 已有
  title: string      // 已有
  date?: string      // 已有
  category?: string  // 已有
  show?: string      // 已有
  episode?: string   // 新增：期数（如"第89期"）
  context?: string   // 新增：上下文摘要（约200字符）
}
```

### 4.2 parseFrontmatter 扩展

backlinks.ts 的 parseFrontmatter() 函数需增加解析 `episode` 字段。

### 4.3 上下文摘要提取

新增 `extractContextSummary(notePath, entityName)` 函数：
1. 读取播客笔记 .md 文件
2. 搜索实体名称首次出现位置
3. 截取前后各约 100 字符
4. 清理 markdown 语法符号
5. 返回摘要字符串

## 5. 非功能需求

| 需求 | 指标 |
|------|------|
| 索引构建性能 | 100 个实体 × 50 篇笔记 < 2 秒 |
| 时间线渲染性能 | 50 条记录 < 500ms |
| 图谱渲染性能 | 50 个节点 + 100 条连线 < 1 秒 |
| 文件读写安全 | 不破坏现有实体卡片内容 |
| 内存占用 | 上下文摘要总量 < 5MB |

无新增 IPC 通道。现有 `backlinks:index` IPC 返回的数据结构扩展（PodcastRef 增加字段），前端直接消费。

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 上下文摘要提取性能慢 | 中 | 索引构建耗时增加 | 限制只搜索前 10000 字符，缓存摘要结果 |
| 实体名称在笔记中被修改 | 低 | 摘要提取失败 | 回退显示"无法提取上下文" |
| SVG 图谱在大量节点时性能差 | 低 | 图谱渲染卡顿 | 节点 > 50 时只显示 Top 50 高频实体 |
| 实体卡片"近期提及"段落被用户手动编辑 | 中 | 自动更新覆盖用户编辑 | 只替换 `## 近期提及` 到下一个 `##` 之间的内容 |
