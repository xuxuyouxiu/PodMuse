## Epic：Obsidian 反向链接面板

**需求来源：** ICE 排序第 2 名（25.0 分）
**描述：** 在应用内展示"哪些播客提到了这个实体"的反向链接视图，激活知识网络
**拆分模式：** 按复杂度递进（基础索引 → 展示面板 → 交互增强 → 跨实体发现）
**拆分粒度：** Sprint 级（1-3 天）
**团队构成：** 全栈（个人项目）

---

### 需求全貌

**涉及角色：** 个人用户（播客笔记助手使用者）

**核心流程：**
1. 用户处理多期播客后，同一实体（人物/项目/概念）可能出现在多期节目中
2. 用户想查看"某个实体在哪些节目中被提到过，分别说了什么"
3. 用户希望从反向链接视图中发现跨节目的知识关联

**现有基础：**
- `appendSourceLink()` 已在实体卡片文件末尾追加 `[[podcastFilename]]` 格式的反向链接
- `search-ipc.ts` 已有文件系统遍历搜索能力
- 实体卡片有 4 种 Obsidian 模板（人物/项目/概念/术语）
- 播客笔记中使用 `[[wiki-link]]` 引用实体

**数据实体：** 实体卡片文件（人物/项目/概念/术语/.md）、播客笔记文件（分类目录/.md）

**业务规则：**
- 反向链接数据源：实体卡片文件中末尾的 `[[播客笔记]]` 链接列表
- 需要解析播客笔记的 frontmatter 获取元数据（日期、节目名、分类、标签）
- 面板仅在已配置 Obsidian 目录时可用

### US-001：反向链接索引服务

**角色：** 作为播客笔记助手用户
**需求：** 我希望系统能自动扫描 Obsidian 目录，构建"实体 → 提及它的播客列表"索引
**价值：** 以便我能快速看到每个实体被多少期节目提到过
**优先级：** P0（必须）
**Story Points：** 5

**Acceptance Criteria：**
- [ ] Given Obsidian 目录已配置, When 调用索引服务, Then 扫描 `人物/`、`项目/`、`概念/`、`术语/` 下所有 `.md` 文件，提取每个文件末尾的 `[[播客笔记文件名]]` 链接，返回 `Map<实体名, 播客文件路径[]>`
- [ ] Given 某实体卡片文件不存在反向链接, When 索引, Then 该实体的播客列表为空数组 `[]`，不报错
- [ ] Given Obsidian 目录未配置或路径无效, When 调用索引服务, Then 返回空索引并记录 warning，不崩溃
- [ ] Given 实体卡片文件末尾混有其他内容（非 wiki-link）, When 提取, Then 仅识别 `[[...]]` 格式的链接，忽略其他文本

**依赖：** 无
**技术备注：**
- 新增 `src/main/backlinks.ts`，导出 `buildBacklinkIndex(obsidianDir: string): BacklinkIndex`
- 接口定义：`interface BacklinkEntry { entityName: string; entityType: 'people'|'projects'|'concepts'|'terms'; podcastPaths: string[] }`
- 实体类型从文件所在子目录名推断（人物→people，项目→projects 等）
- IPC channel：`backlinks:index` → 返回序列化后的索引数据
- preload 桥接：`getBacklinkIndex(): Promise<BacklinkEntry[]>`

### US-002：反向链接展示面板

**角色：** 作为播客笔记助手用户
**需求：** 我希望在应用内有一个面板，展示所有实体及其反向链接概览
**价值：** 以便我能直观看到知识网络的连接情况
**优先级：** P0（必须）
**Story Points：** 5

**Acceptance Criteria：**
- [ ] Given 用户打开反向链接面板, When 索引加载完成, Then 展示所有有反向链接的实体列表，每个实体显示名称、类型图标、提及次数
- [ ] Given 用户点击某个实体, When 展开, Then 显示该实体被提及的播客笔记文件名列表
- [ ] Given 没有任何反向链接数据（新安装或目录为空）, When 打开面板, Then 显示空状态提示"处理更多播客后将在此展示知识关联"
- [ ] Given Obsidian 目录未配置, When 打开面板, Then 显示提示"请先在设置中配置 Obsidian 笔记目录"

**依赖：** US-001
**技术备注：**
- 新增 `src/renderer/components/BacklinkPanel.tsx`，可作为侧边栏或独立页面
- 使用现有 UI 风格（参考设置页的列表展示）
- 实体类型用不同颜色/图标区分（人物→用户图标，项目→文件夹图标，概念→灯泡图标，术语→书签图标）
- 按提及次数降序排列，提及次数相同的按实体名排序

### US-003：播客笔记元数据展示

**角色：** 作为播客笔记助手用户
**需求：** 我希望在反向链接列表中看到每期播客的标题、日期和分类信息
**价值：** 以便我能快速识别哪期节目与当前实体最相关
**优先级：** P1（重要）
**Story Points：** 3

**Acceptance Criteria：**
- [ ] Given 展开某实体的播客列表, When 显示播客条目, Then 每条显示：播客标题（从文件名解析）、日期（从 frontmatter 提取）、分类标签
- [ ] Given 某播客笔记文件的 frontmatter 解析失败, When 显示, Then 降级显示文件名，不显示日期和分类
- [ ] Given 某播客笔记文件已被删除或移动, When 显示, Then 标记为"笔记已移动"，仍可显示文件名信息

**依赖：** US-001, US-002
**技术备注：**
- 扩展 `BacklinkEntry` 添加播客元数据：`interface PodcastRef { path: string; title: string; date?: string; category?: string; show?: string }`
- 索引服务在构建索引时同步读取播客笔记的 frontmatter（只读前 20 行，用正则匹配 YAML）
- 避免读取整个文件内容，减少 I/O 开销

### US-004：点击跳转到播客笔记

**角色：** 作为播客笔记助手用户
**需求：** 我希望点击反向链接中的播客条目，能直接在 Obsidian 中打开对应笔记
**价值：** 以便我能快速查看该实体在节目中的具体上下文
**优先级：** P1（重要）
**Story Points：** 3

**Acceptance Criteria：**
- [ ] Given 用户点击反向链接列表中的播客条目, When 点击, Then 调用 `shell.openPath()` 在系统默认应用中打开该 `.md` 文件（通常为 Obsidian）
- [ ] Given 播客笔记文件不存在, When 点击, Then 显示 toast 提示"笔记文件不存在，可能已被移动或删除"
- [ ] Given 用户右键点击播客条目, When 上下文菜单出现, Then 提供"在文件管理器中显示"选项（`shell.showItemInFolder()`）

**依赖：** US-002
**技术备注：**
- IPC channel：`backlinks:openNote` → 参数 `{ path: string }`，调用 `shell.openPath(path)`
- preload 桥接：`openNoteInObsidian(path: string): Promise<void>`
- 右键菜单用 Electron 原生 `Menu.popup()` 或自定义 React 上下文菜单

---

### US-005：共现实体推荐（跨实体知识发现）

**角色：** 作为播客笔记助手用户
**需求：** 我希望查看某实体的反向链接时，能看到经常与之同时出现的其他实体
**价值：** 以便我能发现跨节目的隐性知识关联（如"张三和李四总在聊 AI 话题"）
**优先级：** P2（Nice-to-have）
**Story Points：** 5

**Acceptance Criteria：**
- [ ] Given 用户选中某实体, When 面板展示反向链接, Then 同时展示"共现实体"区域，列出与该实体出现在相同播客中的其他实体，按共现次数降序
- [ ] Given 共现实体列表, When 用户点击某个共现实体, Then 跳转到该实体的反向链接视图
- [ ] Given 没有任何共现实体（该实体只出现在 1 期节目中）, When 展示, Then 隐藏"共现实体"区域或显示"暂无共现实体"
- [ ] Given 共现实体超过 10 个, When 展示, Then 默认只显示前 5 个，可点击"查看更多"展开

**依赖：** US-001（索引数据）, US-002（面板 UI）
**技术备注：**
- 共现计算：对实体 A 的播客列表 P(A)，遍历索引中所有其他实体 B，计算 `|P(A) ∩ P(B)|` 作为共现次数
- 计算在 renderer 端完成（索引数据已加载），无需额外 IPC
- 性能考虑：实体数量通常 < 500，O(n) 遍历足够

### 风险与待确认项

1. **[已确认]** 反向链接数据源：使用实体卡片文件末尾已有的 `[[podcastFilename]]` 链接，无需改造写入流程
2. **[待确认]** 面板入口位置：是作为主界面的侧边栏、独立 Tab、还是设置页的一个子页？建议作为主界面的侧边抽屉或底部面板
3. **[待确认]** 索引更新时机：每次打开面板时重新扫描 vs 应用启动时构建缓存？建议启动时构建 + 手动刷新按钮，因为 Obsidian 目录通常不大（< 1000 文件），扫描很快
4. **[低风险]** Obsidian 未安装：`shell.openPath()` 会用系统默认应用打开 .md 文件，如果用户没有 Obsidian 但有其他 Markdown 编辑器也能正常工作
