## US-001：实体时间线视图

**角色**：作为播客听众
**需求**：我希望在选中某个实体（人物/项目/概念/术语）后，看到它在多期播客中按时间排列的出现记录，每期附带上下文摘要
**价值**：以便快速了解某个实体在不同期节目中的演变过程，而非只看到一串文件名
**优先级**：P0
**Story Points**：5

**Acceptance Criteria**：

- [ ] Given 用户在知识关联面板点击某实体（如"张三"），When 面板展开，Then 显示该实体的时间线视图，按日期降序排列所有提及该实体的播客笔记
- [ ] Given 时间线视图渲染，When 每条记录显示，Then 每条包含：节目名、期数（如"第89期"）、日期、该播客中实体出现的上下文摘要（1-2句话）
- [ ] Given 实体在 3 期播客中被提及，When 用户查看时间线，Then 3 条记录按日期降序排列，最近一次排在最前
- [ ] Given 实体仅被 1 期播客提及，When 时间线渲染，Then 正常显示 1 条记录，不显示"暂无跨期数据"提示
- [ ] Given 时间线视图中某条记录，When 用户点击该条目，Then 在 Obsidian 中打开对应的播客笔记文件
- [ ] Given 反链索引中 podcastRefs 已有 date 字段，When 构建时间线，Then 复用现有 backlinks.ts 的索引数据，补充解析 frontmatter 中的 episode 字段
- [ ] Given 实体卡片文件末尾有 `- [[播客笔记名]]` 格式的引用列表，When 构建时间线上下文摘要，Then 从对应的播客笔记文件中提取该实体附近的上下文文本（前后各 100 字）

**依赖**：无（建立在现有 backlinks.ts 索引之上）
**技术备注**：
- `backlinks.ts` 的 `parseFrontmatter()` 需扩展，增加解析 `episode` 字段
- `PodcastRef` 接口需增加 `episode?: string` 字段
- `BacklinkPanel.tsx` 中展开实体后的视图从"文件名列表"改为"时间线卡片列表"
- 上下文摘要：读取播客笔记 .md 文件，搜索实体名称，截取前后各约 100 字符作为摘要
- 时间线卡片样式复用 app 的 glass-card 设计语言（var(--bg-card) + backdrop-filter + panel-shadow + radius-lg）

## US-002：跨期观点对比

**角色**：作为播客听众
**需求**：我希望能对比某个实体在不同期播客中的核心观点变化
**价值**：以便发现实体观点的演变轨迹，比如某人物在第10期说的观点和第50期有什么不同
**优先级**：P1
**Story Points**：3

**Acceptance Criteria**：

- [ ] Given 时间线视图中实体有 ≥ 2 条记录，When 面板顶部显示，Then 出现"对比"按钮
- [ ] Given 用户点击"对比"按钮，When 对比视图展开，Then 显示一个并排对比面板，可选择 2-3 期播客进行对比
- [ ] Given 用户选择第10期和第50期，When 对比结果渲染，Then 两期的上下文摘要并排显示，差异部分高亮标注
- [ ] Given 对比视图中，When 用户查看，Then 每期摘要有独立的标题栏显示期数和日期
- [ ] Given 对比视图打开，When 用户点击"关闭对比"，Then 回到时间线列表视图

**依赖**：US-001
**技术备注**：
- 对比视图为前端纯展示组件，数据来自 US-001 已提取的上下文摘要
- 高亮差异可用简单的文本对比（按句子分割，标记新增/删除/变化）
- 最多支持 3 期对比，避免布局拥挤

## US-003：实体关系图谱

**角色**：作为播客听众
**需求**：我希望看到实体之间的关系图谱，展示哪些实体经常在同一期播客中共同出现
**价值**：以便发现潜在的关联和知识网络，比如"提到张三的播客也经常提到李四"
**优先级**：P1
**Story Points**：3

**Acceptance Criteria**：

- [ ] Given 用户在知识关联面板，When 面板顶部显示，Then 有"关系图谱"切换标签
- [ ] Given 用户切换到关系图谱视图，When 图谱渲染，Then 以节点-连线形式展示实体间共现关系，节点大小反映出现频次，连线粗细反映共现次数
- [ ] Given 图谱中某两个实体共现 3 次，When 渲染连线，Then 连线标注"3"且线条较粗
- [ ] Given 图谱中某实体仅出现 1 次，When 渲染节点，Then 节点较小且颜色较淡
- [ ] Given 用户点击图中某节点，When 节点选中，Then 高亮该节点的所有关联连线，并显示该实体的时间线（跳转到 US-001 视图）
- [ ] Given 共现实体数据已由 BacklinkPanel.tsx 的 computeCoEntities() 计算，When 构建图谱，Then 复用现有共现数据

**依赖**：US-001
**技术备注**：
- 复用 BacklinkPanel.tsx 中已有的 `computeCoEntities()` 函数
- 图谱渲染可用 SVG 或 Canvas，节点数一般 < 50，不需要图布局算法
- 力导向布局可选，也可用简单的圆形排列
- 交互：点击节点跳转到时间线视图

## US-004：实体卡片自动更新摘要

**角色**：作为播客听众
**需求**：我希望实体卡片文件中自动维护一个"近期提及"摘要段落，包含最近 3 次被提及的播客标题和日期
**价值**：以便在 Obsidian 中直接浏览实体卡片时就能看到跨期积累结果，不用打开应用
**优先级**：P2
**Story Points**：2

**Acceptance Criteria**：

- [ ] Given 处理完一期新播客且生成了实体卡片更新，When 实体卡片文件写入，Then 在文件中"## 近期提及"段落下添加最新播客的标题和日期
- [ ] Given "近期提及"段落已有 3 条记录，When 新增第 4 条，Then 自动移除最早的记录，保持最多 3 条
- [ ] Given "近期提及"段落格式，When 渲染，Then 每条格式为 `- [[播客标题]] (2026-06-22 第89期)`
- [ ] Given 实体卡片是首次创建，When 写入，Then 在文件末尾添加 `## 近期提及` 标题和首条记录
- [ ] Given 实体卡片已存在"近期提及"段落，When 更新，Then 只替换该段落内容，不影响卡片其他内容

**依赖**：US-001
**技术备注**：
- 修改 `entity-cards.ts` 中的 `appendSourceLink()` 函数，或在其调用后追加摘要更新逻辑
- 用正则匹配 `## 近期提及` 段落，存在则替换，不存在则追加
- 最多保留 3 条，按日期降序排列
- 不影响现有的 `- [[播客笔记名]]` 引用列表
