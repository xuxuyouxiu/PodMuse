# 用户故事 — 导出更多平台

**需求 ID：** ICE 6.0（排名 9）
**版本：** v1.13.0
**状态：** 规划中
**创建日期：** 2026-07-19

---

## 背景与现状

播客笔记助手当前生成的笔记仅写入 Obsidian 库目录（`config.obsidian_dir`，见 `src/main/podcast.ts:578-582`），核心写入逻辑：

```ts
const filepath = path.join(targetDir, `${filename}.md`)
fs.writeFileSync(filepath, notes.content, 'utf-8')
return path.relative(obsDir, filepath)
```

所有处理流程（手动 `podcast:process` / 批量 `batch-queue` / 飞书触发 `podcast-dispatcher`）都汇聚到 `processPodcast()`。生成笔记是 AI 直出的 markdown，frontmatter 字段为 `type/show/episode/title/host/guest/platform/date/duration/status/tags/category/content_type`，正文用 `[[wiki-link]]` Obsidian 双链语法。

**主要不足：**

- 无任何导出能力，`grep -ri "notion\|logseq\|exportTo"` 在 `src/` 零命中
- 无 Notion 集成 SDK（`package.json` 无 `@notionhq/client`）
- 用户若同时使用 Logseq / Notion 维护知识库，必须手动复制粘贴，体验割裂
- RecentTask 完成卡片只有"在 Obsidian 中打开"按钮，无导出入口

**目标：** 在不改变现有 Obsidian 写入主流程的前提下，新增手动触发的多平台导出能力，覆盖 Markdown 文件、Logseq 目录、Notion database 三种目标。

**不做：**

- 批量导出（仅单任务手动触发，避免侵入批量处理流程）
- 自动导出（用户明确选择手动触发，避免配置不当造成重复上传）
- 飞书文档导出（飞书云文档 API 与 IM 通知不同链路，留待后期评估）
- 印象笔记 / OneNote / Bear（用户基数小，ROI 低）

## US-001 Markdown 文件导出 — 通用目录复制（P0）

**作为** 已生成播客笔记的用户，**我想** 把笔记导出到 Obsidian 库以外的任意目录（本地 Markdown 库、U 盘、网盘同步目录），**以便** 在不依赖 Obsidian 的情况下也能查看和归档笔记内容。

**验收标准：**

1. 新增 IPC channel `export:toMarkdown`，入参 `{ taskId: string; targetDir: string; stripObsidianSyntax?: boolean }`，出参 `{ success: boolean; outputPath: string; error?: string }`。
2. 实现逻辑：
   - 从 `recentTasks` 读取任务对应的 `notePath`（绝对路径），若文件不存在返回 `{ success: false, error: '源笔记文件不存在' }`
   - 复制 `.md` 文件到 `targetDir`，保留原文件名
   - 若 `stripObsidianSyntax=true`，对内容做转换：`[[xxx|alias]]` → `alias`（若有 alias）或 `xxx`；`[[xxx]]` → `xxx`。frontmatter 原样保留
   - 文件名冲突处理：目标已存在同名文件时，新文件名追加时间戳 `_YYYYMMDDHHmmss` 后缀
3. 目录可写性检查：写入前用 `fs.accessSync(targetDir, fs.constants.W_OK)` 验证，失败返回友好错误
4. 错误处理：磁盘满 / 路径过长 / 权限不足 → catch `NodeJS.ErrnoException`，按 `code` 映射中文提示
5. 成功后返回绝对路径，由前端 toast 通知 + 提供打开目录链接

## US-002 Logseq 目录导出（P1）

**作为** 同时使用 Logseq 维护知识库的用户，**我想** 把播客笔记直接复制到 Logseq graph 目录，**以便** 在 Logseq 中也能检索、关联和图谱化笔记。

**验收标准：**

1. 设置面板新增"导出"分组，包含 `logseq_dir` 配置项（目录选择器，复用现有 `dialog:selectDir` IPC）。
2. 配置持久化到 `podcast_config.json`，结构：`"export": { "logseq_dir": "", "notion": { "token": "", "database_id": "" } }`。
3. 新增 IPC channel `export:toLogseq`，入参 `{ taskId: string }`，出参同 US-001。
4. 实现逻辑：
   - 读取 `config.export.logseq_dir`，为空时返回 `{ success: false, error: '未配置 Logseq 目录，请在设置中配置' }`
   - 复制 `.md` 文件到 logseq_dir，**保留**原 frontmatter 和 wiki-link 格式（Logseq 与 Obsidian 语法兼容）
   - 文件名冲突处理同 US-001
5. 前端导出菜单：logseq_dir 已配置时显示"Logseq"项并启用，未配置时显示但禁用，悬停提示"未配置 Logseq 目录"
6. 复用 US-001 的复制核心函数（提取 `copyNoteToDir(srcPath, targetDir, { stripObsidianSyntax })` 公用）

## US-003 Notion 导出 — API 集成上传到 Database（P1）

**作为** 在 Notion 中维护播客知识库的用户，**我想** 把播客笔记上传到指定的 Notion database，**以便** 在 Notion 集中管理所有播客笔记、按 database properties 筛选、与团队协作。

**验收标准：**

1. 设置面板"导出"分组新增 Notion 配置：`token`（Integration Token，password 输入框）+ `database_id`（URL 或 ID 输入框）+ "测试连接"按钮。
2. 新增 IPC channel `export:notion:testConnection`，入参 `{ token: string; databaseId: string }`，出参 `{ success: boolean; databaseTitle?: string; error?: string }`。测试逻辑：调用 `https://api.notion.com/v1/databases/{id}` 验证 token 有效 + database 可访问。
3. 新增 IPC channel `export:toNotion`，入参 `{ taskId: string }`，出参 `{ success: boolean; pageUrl?: string; pageId?: string; error?: string }`。
4. 上传逻辑：
   - 读取 `config.export.notion.token` + `database_id`，任一为空返回友好错误
   - 解析笔记 frontmatter，把以下字段写入 database properties（需 database 有对应列）：
     - `title` → Notion `title` property（必填，无则用笔记文件名）
     - `show` → `rich_text` property
     - `episode` → `rich_text` property
     - `date` → `date` property
     - `category` → `select` property
     - `tags` → `multi_select` property（按 `,` 拆分）
     - `host` / `guest` → `rich_text` property
     - `platform` → `select` property
   - 正文 markdown 通过简易转换写入页面内容块（标题/段落/列表/引用/blockquote 转换为对应 Notion block；`[[wiki-link]]` 转纯文本 `wiki-link`）
   - 调用 `POST https://api.notion.com/v1/pages`，header `Authorization: Bearer ${token}` + `Notion-Version: 2022-06-28`
5. 重复检测：上传前调用 `POST /v1/databases/{id}/query` 按 title 查询是否已有同名页面，存在则返回 `{ success: false, error: 'Notion database 中已存在同名页面，请先手动处理或修改笔记标题', existingPageUrl?: string }`
6. 错误处理：token 失效（401）/ database 不存在（404）/ 速率限制（429）/ 网络错误 → 按状态码映射中文提示
7. 成功后返回 Notion 页面 URL，前端 toast 通知 + 提供"在浏览器中打开"链接

## US-004 导出配置 UI 与触发按钮（P0）

**作为** 用户，**我想** 在 RecentTask 完成卡片看到导出按钮，并在设置中统一管理导出平台配置，**以便** 一键把笔记导出到我常用的平台。

**验收标准：**

1. `RecentTask` 完成卡片新增"导出"按钮（图标 `Share` 或 `Download`，来自 lucide-react），位于"在 Obsidian 中打开"按钮旁。
2. 点击按钮弹出下拉菜单（复用项目现有 Popover / DropdownMenu 组件），内容：
   - **Markdown…**（始终启用）→ 弹出系统目录选择对话框 → 调用 `export:toMarkdown`
   - **Logseq**（logseq_dir 已配置时启用）→ 直接调用 `export:toLogseq`
   - **Notion**（notion token + database_id 已配置时启用）→ 直接调用 `export:toNotion`
   - 未配置项显示但禁用，悬停提示"在设置中配置"
3. 设置面板（`SettingsPanel.tsx` 或对应文件）新增"导出"分组：
   - Logseq 目录：目录选择器 + 当前路径显示
   - Notion：token（password 输入） + database_id + "测试连接"按钮 + 测试结果显示
4. 配置保存到 `podcast_config.json`，与 `obsidian_dir` 同级结构。
5. 导出过程 UX：
   - 点击导出后按钮变为 spinner + "导出中..."
   - 成功：toast 绿色通知 "已导出到 {平台名}"，Markdown 提供打开目录链接，Notion 提供打开页面链接
   - 失败：toast 红色通知显示具体错误
   - 导出中按钮禁用，防止重复点击
6. 国际化：所有用户可见文案使用中文（与项目现有 UI 一致）。

## 非功能需求

1. 不引入 `@notionhq/client` 官方 SDK（与项目"依赖最小化"风格一致），用 `fetch` 直接调 Notion REST API。
2. 不引入 markdown 解析库（如 `marked` / `remark`），用极简字符串解析（按行 split + 正则匹配 `#` / `>` / `-` / `[[`）。
3. 配置项含密钥（notion token）走现有 `config:save` 持久化路径，不写入 git（`podcast_config.json` 已在 `.gitignore`）。
4. 导出操作不阻塞主进程：用 `fs.promises` + Notion fetch 异步调用，避免 IPC handler 卡顿。
5. 网络请求超时 30s（Notion API）。
6. 源笔记路径来自 `recentTasks` 中的 `notePath`，若任务未完成或文件已被删除，给出明确错误。

## 已排除

- **飞书云文档导出**：飞书云文档 API 与现有 IM 通知是不同链路（IM 用 `im:message:send`，云文档需 `docx:document:create` 等高权限 scope），scope 升级需用户重新授权，留待后期评估。
- **印象笔记 / OneNote / Bear**：用户基数小，API 成本高，ROI 低。
- **批量导出**：本期不做，避免侵入批量处理流程，留待用户反馈。
- **自动导出（笔记生成后自动推送）**：用户明确选择手动触发，避免配置不当造成重复上传或失败堆积。
- **导出历史记录**：低频需求，留待后期。
