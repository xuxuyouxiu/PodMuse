# 播客笔记助手窄屏表单堆叠设计

日期：2026-05-26

## 目标

- 修复窗口收窄后主工作区输入卡横向排版被挤坏的问题。
- 保持窄屏时“最近任务”继续堆叠到底部，不恢复右侧栏布局。
- 让“开始处理”按钮在窄屏下完整可见，不再被裁切或挤压到边界。

## 范围

本次只处理窄屏状态下主工作区欢迎卡和输入卡的布局收紧，不改业务逻辑。

- 保留 `1100px` 左右以下时主工作区与最近任务上下堆叠的方向。
- 将输入卡在窄屏下切换为纵向表单布局。
- 收紧欢迎卡和输入卡在窄屏下的上下内边距与区块间距。

不在本次范围内：

- 恢复右侧栏布局
- 修改最近任务面板内容和逻辑
- 修改顶部工具栏结构
- 修改处理逻辑、Whisper、飞书监听、最近任务状态机

## 问题定义

当前在较窄窗口下，整体已经切成上下堆叠，但输入卡仍沿用宽屏时的横向输入区：

- 输入框与按钮仍试图同排
- 卡片宽度不足时按钮被顶到右边界
- 卡片本身仍保留较强的横向布局感，导致视觉上显得扁且挤

因此，问题不在“最近任务掉到底部”，而在于“主工作区卡片没有进入窄屏表单模式”。

## 选定方案

采用“窄屏纵向表单”方案。

核心思路：

- 在当前窄屏断点下，保留主区和最近任务上下堆叠
- 仅让输入卡内部从横向改为纵向
- 同时把欢迎卡和输入卡切到更紧凑的窄屏间距

选择理由：

- 与用户选择一致
- 改动最小，只修当前截图里最明显的问题
- 不需要推翻已经确认的“最近任务放底部”布局决策

## 布局设计

### 最近任务区域

保持现状：

- 在窄屏下继续位于主工作区下方
- 不尝试恢复为右侧栏
- 不额外隐藏或折叠

这意味着本次优化重点全部放在主工作区卡片的自适应方式上。

### 欢迎卡

欢迎卡在窄屏下进入紧凑模式：

- 上下 padding 进一步收紧
- 标题与描述文案间距略缩小
- 状态徽标保留，但与文本区的对齐更紧凑

目标效果：

- 在窄屏下减少垂直占高
- 与下方输入卡的节奏更统一

### 输入卡

输入卡在窄屏下由横向操作区切换为纵向表单：

- 输入框单独占一行
- `开始处理` 按钮换到下一行
- 按钮宽度不再被横向挤压，可以使用自适应宽度或直接铺满可用宽度
- 标题、提示文案和表单区之间的间距一并收紧

目标效果：

- 按钮完整显示
- 输入区不再显得“横向强撑”
- 窄屏下更像自然的移动式/紧凑式表单

## 技术实现

### `src/renderer/styles/globals.css`

主要改动放在现有窄屏媒体查询中：

- 为 `workspace-hero` 增加更紧凑的窄屏 padding
- 为 `workspace-input-card` 增加更紧凑的窄屏 padding
- 为 `url-input-actions` 在窄屏下改为纵向布局
- 为 `url-input-field` 和 `url-input-submit` 补充窄屏宽度规则
- 必要时收紧 `url-input-card` 的 gap 和标题区间距

### `src/renderer/components/UrlInput.tsx`

原则上不改业务逻辑。

只有在现有 class 不足以支撑样式选择时，才补最小 class hook；若现有 class 已够用，则不修改该文件。

### `tests/ui-theme-source.test.mjs`

新增静态断言，锁定本次窄屏布局约束：

- `@media (max-width: 1100px)` 下 `url-input-actions` 改为纵向
- `url-input-submit` 在窄屏下有明确宽度策略
- `workspace-hero` / `workspace-input-card` 在窄屏下有更紧凑的 padding

## 验证标准

- 当前这种较窄窗口宽度下，“开始处理”按钮完整可见
- 输入框和按钮不再在同一行里互相挤压
- 最近任务仍在底部展示，不回退为右侧栏
- 欢迎卡与输入卡在窄屏下显得更紧凑，不再过高过空
- 宽屏布局不回退

## 风险与控制

- 风险：按钮改到下一行后显得过长
  控制：优先用容器宽度自适应，必要时限制最大宽度

- 风险：窄屏 padding 收得太狠导致卡片显得拥挤
  控制：只在 `1100px` 下收一档，保留清晰的留白下限

- 风险：样式只修输入卡，欢迎卡仍显得偏空
  控制：将欢迎卡与输入卡一并纳入窄屏紧凑模式

## 结论

本次采用“窄屏纵向表单”方案：

- 最近任务继续放到底部
- 欢迎卡进入紧凑模式
- 输入卡在窄屏下切成输入框一行、按钮一行

这样可以在不推翻现有整体布局的前提下，直接修复你截图里最明显的窄屏排版问题。
