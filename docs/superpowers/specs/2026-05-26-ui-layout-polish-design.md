# 播客笔记助手 UI 布局精修设计

日期：2026-05-26

## 目标

- 修复右侧最近任务面板位置过高的问题，使其整体下移到顶部工具栏下方。
- 修复主工作区内容显示不完整的问题，保证内容区域可以独立滚动。
- 调整顶部标题栏区域的排布，减少当前元素互相挤压和换行错位。
- 将最小化、最大化、关闭按钮固定在右上角，避免受中间内容宽度影响。

## 范围

本次仅处理布局和样式，不新增功能，不修改已有处理语义。

- 保留当前三栏工作台结构：左侧装饰栏、中间主工作区、右侧最近任务面板。
- 保留当前顶部工具栏中的品牌、搜索占位、飞书状态和主题切换。
- 保留最近任务列表、恢复任务、重新处理、删除任务的现有逻辑。
- 保留当前主题切换和响应式规则，在此基础上做局部修正。

不在本次范围内：

- 飞书监听和任务轮询逻辑
- Whisper 转写和笔记处理逻辑
- 最近任务的数据结构和状态机
- 设置弹窗内容和 IPC 接口

## 约束

- 继续遵守“最小改动”原则，只调整容器层级、滚动容器和布局样式。
- 不把右侧任务区改成底部模块，仍保持独立侧栏。
- 不重做整套视觉风格，只修正当前布局缺陷。
- 响应式修复必须兼容当前已经存在的中小窗口兜底规则。

## 选定方案

采用“保留三栏结构，只重排右侧栏和顶栏”的方案。

选择理由：

- 与用户确认的“右侧栏整体下移”一致。
- 能解决当前位置错位和工作区裁切问题，同时避免重新设计整页结构。
- 只需要改动 `App.tsx`、`Header.tsx`、`globals.css` 及对应静态测试，回归风险最低。

## 布局设计

### 整体结构

当前结构中，右侧任务面板直接挂在整页最外层，视觉上与顶部工具栏并列，因此会显得过高。

调整后采用以下层级：

- 左侧仍为 `WorkspaceSidebar`
- 中间主区仍为 `workspace-main`
- 顶部仍为 `Header`
- 顶部以下新增统一内容层，内部再横向分为：
  - 左侧主工作区内容
  - 右侧最近任务面板

这样右侧面板的起始位置会与主工作区内容对齐，自然落到顶部工具栏下方，而不是贴着整窗顶边。

### 主工作区滚动

主工作区继续作为独立滚动区域，但需要明确滚动边界，避免外层容器把高度吃掉后导致内容显示不完整。

调整要求：

- 顶部工具栏保持固定，不参与主区滚动。
- 工具栏下方的内容层必须设置 `min-height: 0`。
- 主工作区列必须设置 `min-width: 0` 和 `overflow-y: auto`。
- 欢迎区、链接输入卡、流程卡保持当前顺序，不重新拆块。

目标效果：

- 当流程区内容较长时，用户可直接在中间区向下滚动看到完整内容。
- 顶栏和右侧栏不再因为主区内容过长而被挤压。

### 右侧任务面板

右侧任务面板保持独立卡片，但位置和高度策略调整如下：

- 整体起始位置与主工作区内容顶部对齐
- 面板自身占满内容层可用高度
- 面板内部的任务列表继续单独滚动
- 顶部摘要区保留固定高度，不与列表抢空间

目标效果：

- 视觉上属于“内容区的一部分”，而不是“挂在标题栏旁边”
- 任务多时只滚动列表，不影响整个页面

## 顶部工具栏设计

### 顶栏分区

顶栏保持一行主布局，分为三个区域：

- 左侧：应用图标与名称
- 中间：搜索占位区
- 右侧：飞书状态、主题切换

窗口控制按钮从现有内容流中拆出来，作为顶栏右上角的独立区域存在。

### 窗口按钮固定

窗口按钮需要满足两个条件：

- 永远位于右上角
- 不受搜索区和状态区换行影响

为达到这个效果，顶栏需要区分“内容区”和“窗口按钮区”：

- 内容区负责品牌、搜索、状态、主题切换
- 窗口按钮区固定贴右，并始终 `no-drag`

这样即使中间区域在较窄宽度下收缩，窗口按钮也不会掉到下一行或漂移到中部。

## 文件影响

### `src/renderer/App.tsx`

需要调整主内容层级：

- 将右侧 `workspace-aside` 从整页最外层并列结构，改为挂到顶部工具栏下方的统一内容层中
- 保持 `Header` 独立在滚动内容之上
- 保持 `RecentTasksSidebar` 的 props 和业务行为不变

### `src/renderer/components/Header.tsx`

需要调整顶栏内部结构：

- 给“内容区”和“窗口按钮区”提供稳定的布局挂钩
- 确保搜索区、中间状态区和右侧控制区的宽度收缩规则更明确
- 保持现有窗口控制调用方式不变

### `src/renderer/styles/globals.css`

需要补充和修正以下样式：

- 顶部以下统一内容层的高度约束
- 主工作区的独立滚动和 `min-height: 0`
- 右侧任务栏的下移、拉伸和内部滚动
- 顶栏内容区与窗口按钮区的固定排布
- 中小窗口下的兼容规则，避免新结构破坏现有响应式布局

### `tests/ui-theme-source.test.mjs`

新增静态断言，锁定本次结构约束：

- `App.tsx` 存在工具栏下方的统一内容层
- `Header.tsx` 存在窗口按钮独立区域
- `globals.css` 对主区滚动和右侧栏位置提供专用样式钩子

## 验证标准

- 右侧最近任务面板出现在顶部工具栏下方，而不是贴近整窗顶部
- 主工作区可以完整纵向滚动，流程卡和控制区不会被裁掉
- 顶部标题栏在常规窗口宽度下保持稳定，不出现明显错位
- 窗口最小化、最大化、关闭按钮始终固定在右上角
- 当前主题切换、飞书状态显示、最近任务操作保持可用
- 现有中小窗口响应式行为不出现明显回退

## 风险与控制

- 风险：调整 `App.tsx` 层级后影响现有响应式布局
  控制：保留原三栏结构语义，只新增一层内容包装，不改变组件职责

- 风险：顶栏按钮固定后影响拖拽区域
  控制：继续使用 `WebkitAppRegion`，仅交互控件区域设置为 `no-drag`

- 风险：滚动容器嵌套导致部分区域无法滚动
  控制：只保留“主工作区滚动 + 右侧列表滚动”两层必要滚动，避免多余外层滚动

## 结论

本次 UI 精修采用最小侵入方案：

- 不改业务逻辑
- 不改三栏工作台方向
- 只解决右侧栏位置、主区滚动、顶栏排布和窗口按钮固定四个问题

这样可以在最小风险下修复当前最明显的布局缺陷，并保持之前已经完成的主题与响应式改造成果。
