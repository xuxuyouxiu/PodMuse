# 播客笔记助手弹性卡片布局设计

日期：2026-05-26

## 目标

- 让“粘贴链接开始处理”卡片在大窗口和小窗口下都保持更自然的高度与留白。
- 让“当前处理阶段 / 等待处理任务”卡片不再依赖固定大高度，而是根据窗口可用空间动态伸缩。
- 避免最大化时流程卡中间出现明显空白，同时保证缩小窗口时卡片内容仍然完整可读。

## 范围

本次只调整两张主卡片的布局和样式，不新增功能，不改变处理流程。

- 调整 `workspace-input-card` 与 `workspace-process-card` 的外层间距和高度策略。
- 调整 `StepPanel` 在空态和普通态下的最小高度、内容对齐方式和内部留白。
- 保持输入框、按钮、步骤状态、进度信息和控制条的现有业务逻辑不变。

不在本次范围内：

- 飞书监听、Whisper、最近任务逻辑
- 顶部工具栏与右侧最近任务栏结构
- 主题系统和颜色体系
- 控制条按钮行为与 IPC

## 问题定义

当前两个问题来自“固定尺寸思路”：

- 输入卡和流程卡外层使用固定较大的 `padding`，在中小窗口下会显得偏空。
- `StepPanel` 空态和普通态使用固定 `minHeight: 280` 与固定 `padding: 32px 40px`，导致：
  - 最大化时中间视觉空白明显
  - 缩小窗口时内容收缩不够自然

因此，本次不再继续堆固定像素值，而改为“弹性高度 + 弹性间距”。

## 选定方案

采用“视口驱动的弹性卡片”方案。

核心思路：

- 外层卡片使用 `clamp()` 控制上下内边距和区块间距。
- 流程卡改为弹性容器，优先占据剩余高度，但自身空态区域不再写死成大块固定高度。
- `StepPanel` 的空态与普通态通过 class 驱动样式，根据可用空间自动收缩或放大。

选择理由：

- 符合用户提出的“最大化时自然填充、缩小时同步收缩”。
- 比单纯缩小固定高度更稳定，不会只修一个窗口尺寸。
- 只需要改 `globals.css`、`StepPanel.tsx` 以及少量静态测试，风险较低。

## 布局设计

### 输入卡

输入卡目标是“始终紧凑，但不拥挤”。

调整原则：

- `workspace-input-card` 的上下 padding 改成弹性值
- `url-input-card` 的垂直间距改成弹性值
- 标题与提示文案之间的间距略收紧
- 输入框与按钮的横向关系保持不变，优先保证可点击性与熟悉感

目标效果：

- 大窗口下依然有足够呼吸感
- 中小窗口下不会因为固定大留白而显得空

### 流程卡

流程卡目标是“占据剩余空间，但不制造死空白”。

调整原则：

- `workspace-process-card` 继续承担主内容区底部大卡片的角色
- 外层 padding 改为弹性值
- 卡片允许随主区可用高度拉伸
- 内部 `StepPanel` 内容区在大窗口下居中展示，在小窗口下自动收紧

目标效果：

- 最大化时流程卡看起来饱满、稳定
- 小窗口时卡片高度和内部留白一起收缩，不会占掉过多空间

### StepPanel 空态

空态是本次最关键的调整点。

当前问题：

- 等待态图标、标题和说明文案被放在一个固定高的大盒子中央
- 高度大时显得空，高度小时又不够灵活

调整方案：

- 去掉当前内联固定 `minHeight: 280`
- 改为 class 驱动的弹性高度规则，例如：
  - 保留可读性的最低高度
  - 随视口变化逐步增加高度
  - 设置上限，避免最大化时空白过多
- 图标、标题、说明文案的间距一并改为弹性值
- 内容继续居中，但在较小空间下优先压缩间距而不是强行维持大块空白

### StepPanel 普通态

普通态也不应继续依赖与空态相同的固定大高度。

调整方案：

- 普通态容器也改为 class 驱动
- 保留步骤轨道、摘要卡、成功/暂停/失败状态的现有结构
- 在高空间下保持舒展，在低空间下优先压缩上下留白

目标效果：

- 处理中、完成、暂停等状态在不同窗口下都更稳
- 不会因为单一固定高度导致布局僵硬

## 技术实现

### `src/renderer/styles/globals.css`

主要承担弹性布局规则：

- 为 `workspace-input-card`、`workspace-process-card` 增加弹性 padding
- 为 `url-input-card` 增加弹性 gap
- 新增 `step-panel-card--idle`、`step-panel-card--active`、`step-panel-body--idle` 等 class 的样式
- 使用 `clamp()` 和必要的 `min-height` / `max-height` 组合来替代硬编码固定高度
- 在现有 `1280px` / `1100px` 响应式规则基础上补充更适合卡片收缩的约束

### `src/renderer/components/StepPanel.tsx`

主要做结构去内联化：

- 把当前空态和普通态里写死的 `minHeight`、`padding` 等内联样式迁移为 class
- 给空态、普通态、空态内容区补充语义化 class
- 尽量保留现有 JSX 结构和状态逻辑，不重写流程显示逻辑

### `tests/ui-theme-source.test.mjs`

新增静态断言，锁定本次布局原则：

- `StepPanel.tsx` 不再依赖固定 `minHeight: 280`
- `StepPanel.tsx` 暴露空态 / 普通态 class
- `globals.css` 中存在针对主卡片弹性 padding 和 `StepPanel` 弹性高度的样式钩子

## 验证标准

- 最大化窗口时，流程卡不会出现明显不自然的大块空白
- 缩小窗口时，输入卡和流程卡会同步收紧
- 输入框、按钮、步骤轨道、摘要卡和控制条仍完整可见
- 空态“等待处理任务”区域仍然居中，但视觉更紧凑
- 处理中、完成、暂停、失败状态布局不回退
- 现有主题切换和响应式布局不被破坏

## 风险与控制

- 风险：弹性高度过度收缩，导致小窗口下文字拥挤
  控制：通过 `clamp()` 保留明确下限，优先压缩留白，不压缩关键交互控件

- 风险：`StepPanel.tsx` 去内联样式后影响现有状态展示
  控制：只迁移高度、padding、对齐相关样式，不动状态判定和文案

- 风险：流程卡在不同状态下高度表现不一致
  控制：空态和普通态分别提供 class，但共用同一套弹性原则

## 结论

本次采用“弹性卡片”方案，核心不是简单把卡片变矮，而是让它们根据窗口大小自然伸缩：

- 大窗口下更饱满
- 小窗口下更紧凑
- 不再依赖固定大高度和固定大留白

这样可以同时解决你指出的“最大化时空、缩小时又不跟着缩”的两个问题。
